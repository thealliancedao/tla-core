What this is

A record of what gets proposed, asked, promised and announced in the public Terra Telegram groups, so that anyone can see whether an idea has come up before, who raised it first, what questions never got an answer, and what was promised. Every row links to the original message on Telegram. Nothing is quoted without its link.

It is built by a script, not curated by a person. The script, the prompt, the model and every rule are published below and in the code repository, so the whole thing can be re-run by anyone who is a member of the same groups.

What it is not

  • It is not a copy of the chats. The message text is not republished; the board holds a one-line neutral summary and the link.
  • It does not rate people. The labeling model also reads tone and stance, and those fields exist in the maintainer's private working copy — they are deliberately not published, because a model misreads sarcasm, in-jokes and context often enough that a public "who is hostile" table would be unfair to named people. What is public is limited to: ideas, questions, open questions, commitments, announcements, support.
  • Labels are one model's reading of one message. They are not a verdict and never infer motive. Read the original before quoting a count.
  • Direct messages, private groups and anything from a group whose history is not open to members are never imported.

"substantive" = non-bot messages of 40+ characters, or any message containing a question mark of 12+ characters; shorter messages (gm, lol, stickers) are counted as chatter by rule and never sent to the model. The content hash is computed from message ids, timestamps and a hash of each message's text — see step 5 below for how to recompute it.

How a message gets its labels

1 · exportTelegram Desktop → Export chat history → HTML, text only, from the beginning of the group
2 · ingestparsed into a local SQLite store; duplicates skipped; bots and stickers dropped; reactions and reply links kept
3 · ruleunder 40 chars and no "?" → chatter, no model involved
4 · modelbatches of 15 messages, each with the message it replies to and the two before it; claude-haiku-5-5 for posts, claude-sonnet-5-5 for replies; temperature default; the exact prompt below
5 · buildstatic pages from the store; private fields stripped for the public build; this page generated from the same config

Fields the model returns

kind idea · question · answer · feedback · support · criticism · commitment · announcement · chatter · other   topics up to 4 short tags   summary ≤ 20 words, neutral   targets which teams/people the message is about   notable worth a human look

Also returned but not published: tone, stance per target, stance toward the person replied to, whether a reply addresses the point, and observable reply moves.

## Reading rules specific to this community
- "PD" and "PF" are the same organisation at different times. "Phil"/"Philipp"/"Lord Phillip" = 0xPhilipp. "The foundation" = PF.
- "Bribes" is the normal word for TLA incentives — not an accusation. "NWV" = No-with-veto vote. "ES" = emergency supervisor. "msig" = multisig. "VP" = voting power. "LA"/"TLA" = the Alliance. "amp*" = Eris liquid-staked token.
- Criticism of a PRODUCT (Votion, ampCAPA, Estima) is not criticism of a PERSON unless the person is named. Supporting Eris products while criticising Philipp is common — label both.
- Sarcasm is frequent ("Cool. You can still ha…", "Do I have to do all your homework"). Praise of a side's own camp in a dispute is "support"; "I totally support Philip" is support with stance for 0xPhilipp.
- "AI blah blah" / "AI hallucinated" = dismissing a post as machine-written, a dismissal move.




Return ONLY a JSON array, one object per input message, same order, no prose, no code fences. Keep every string short
(summary <= 20 words; topics <= 4 items). Escape double quotes inside strings. Fields:
- "ref": the input ref string, copied exactly
- "kind": one of ['idea', 'question', 'answer', 'feedback', 'support', 'criticism', 'commitment', 'announcement', 'chatter', 'other']
    idea = proposes something new or a concrete change; question = asks something that expects an answer;
    answer = answers a question; feedback = evaluates a product/process/proposal (not a person);
    support = expresses support for a team/person/proposal; criticism = criticises a team/person/proposal;
    commitment = the author (or the team they speak for) promises or states they WILL do something, or sets a deadline
      ("we will hand over the admin key by Friday", "fix ships next week", "I'll post the proposal tomorrow");
    announcement = links or reports news/props/results; chatter = banter, gm, memes, small talk; other.
- "tone": one of ['constructive', 'neutral', 'hostile']
    constructive = offers reasons, data, or a path forward; neutral = plain statement/question;
    hostile = insults, mockery, accusations of bad character, threats, or sustained personal attack.
    Strong disagreement with reasons is NOT hostile. Sarcasm aimed at a person IS hostile.
- "stance": "for" | "against" | "mixed" | "none"  — the OVERALL stance of the message
- "stances": object {target: "for"|"against"|"mixed"|"none"} with one entry PER target listed in "targets".
    A message can be for one target and against another ("Eris keeps Terra alive, PF is dead weight" ->
    {"Eris Protocol": "for", "Phoenix Foundation (PF/PD)": "against"}). Mentioning a target neutrally = "none".
- "targets": list of teams/people the message is ABOUT (not the author), from this vocabulary when it fits:
    teams ['Eris Protocol', 'Phoenix Foundation (PF/PD)', 'Alliance DAO', 'Lion DAO', 'Solid / Capapult', 'Votion', 'Creda', 'Estima', 'Astroport', 'Galactic Punks', 'BackBone Labs', 'SkeletonSwap', 'Atrium', 'Boost DAO', 'Terra Classic', 'TFL', 'Binance', 'Kraken', 'Noble', 'Neutron']
    people ['0xPhilipp', 'MB', 'Rose', 'Vini', 'David', 'Rebel Defi', 'DeFi_Patriot', 'Max Power', 'PFC', 'Rarma', 'Vegas', 'marcus9490', 'Usaf', 'Daniel', 'Niels Banana', 'Llewyn', 'Ryan', 'Evan', 'Crypto Bull', 'Floris', 'Rio', 'Matt', 'Interstellar', 'Smart Stake', 'Polkachu', 'Stakely', 'Orbital Command']
    Use other names only if clearly named in the message. Empty list if none.
- "topics": up to 4 short tags, lowercase (e.g. "votion", "bribes", "a272", "prop 4856", "admin key", "grants", "salaries", "fifth director", "creda", "solid", "liquidity", "validators", "tla")
- "to_parent": ONLY when the input has a "reply_to": the author's stance toward the PERSON they reply to:
    "for" (backs/defends/agrees with them), "against" (opposes/criticises/attacks them), "mixed", "none" (neutral or not about them). Else "none".
- "addresses": ONLY when the input has a "reply_to" that is a question, criticism or request: does this reply deal with it?
    "direct" (answers / engages the actual point), "partial" (engages part, skips the hard part), "none" (does not engage it at all). Else "".
- "moves": ONLY for replies; zero or more of, literally observable in the text (never inferred intent):
    "counter-question" (answers with a question back), "subject-change" (talks about something else),
    "ad-hominem" (goes after the asker's character/motives instead of the point), "misstates-other" (restates the other
    person's words differently from what the reply_to text actually says), "denies-prior" (denies having said/done
    something; flag only — not verified here), "dismissal" ("not worth answering", "cope", mockery instead of substance),
    "concedes" (admits a point or error), "evidence" (brings a link, number, tx, quote or document), "defers" (promises to answer later).
- "summary": <= 20 words, neutral, what the message says (not what you think of it)
- "notable": true only if a human should read it: a new idea, a specific factual claim about a team/person, a promise/commitment, a question left for someone, or a direct accusation. Chatter is never notable.

Known limits

  • Sarcasm and in-jokes are the main source of wrong labels.
  • Display names change and deleted accounts all read as "Deleted Account"; aliases are merged by hand in roles.json only when verifiable.
  • Reactions come from the export, which lists only the first few reactors; totals are correct, names are partial.
  • Roles (badges) are added by hand only with a proof line (on-chain, a proposal, a public announcement) and are listed in roles.json.
  • A message that the model fails to label after several tries is stored as "other" and retried on the next run.
  • The maintainer is a participant in these groups and a council member of Alliance DAO. That is a reason to check the work, which is why everything needed to check it is here.

Hand checks

No hand-check has been published yet. The method below is complete, but treat every count as unverified until an agreement rate appears here.

Corrections and exclusions

No label is ever edited in the database. A hand correction goes in overrides.json with a dated note and the row is marked ✎ on the board; the original model label stays in the store and in the manifest hash. A row is excluded only for doxxing or illegal content, never for being unflattering, and every exclusion is listed here with its reason.

Check it yourself

  1. Be a member of the groups. The eight groups are listed above with their links. Everything here comes from their public history; if you can read them, you can reproduce this.
  2. Export a group. Telegram Desktop → open the group → ⋮ → Export chat history → format HTML, untick photos/videos/stickers/files, leave the dates blank. Large groups export as messages.html, messages2.html … — keep them all in one folder.
  3. Get the code. https://github.com/thealliancedao/tla-core/tree/main/social-board — Python 3.10+, no other dependencies. config.json and context.md are the exact ones used for this build (compare the prompt hash above with python verify.py --prompt).
  4. Ingest your export. python ingest.py <your export folder>. Your store now holds the same messages ours does for that group.
  5. Compare the content hash. python verify.py --manifest https://theadao.com/social/data/manifest.json recomputes the per-group hash from your store and prints match / mismatch, with the first differing message id if any. A match means we did not add, drop or alter a single message in that group.
  6. Re-label a sample with your own key (optional, a few cents). python verify.py --relabel 50 picks 50 random labeled messages, labels them again with the published prompt and model using your API key, and prints the agreement with the published labels. The agreement rate you get should be close to the hand-check rate above.
  7. Check any single count. Every number on the board opens the rows behind it; every row has an open ↗ link to the message on Telegram. If a label looks wrong, say so in the AllianceDAO group or on the forum with the message link; it goes through the correction process above and the change is visible in the next build and in the folder's commit history.
  8. Watch the history. Every build is a dated commit to social-board/public/ in the shared tla-core repository: https://github.com/thealliancedao/tla-core/commits/main/social-board/public. A diff shows exactly which rows changed between any two builds.
